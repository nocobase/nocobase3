# 做复杂功能

订单管理再加权限、审批和通知，就不再是一个表单了。先把业务流程拆成可验证的小目标，每轮确认结果，再继续下一轮。

## 先确认流程，再拆任务

可以先让 AI Agent 整理方案：

```text
我们已经能新增和编辑订单。
接下来要增加主管审批，通过后通知申请人。
请先列出业务状态、角色和需要确认的问题，再给出分步方案。
这一轮先不改代码。
```

你需要确认的通常是业务决定：谁能提交、谁来审批、拒绝后怎么办、已批准的数据能不能修改。AI Agent 可以帮助整理，但不能替团队决定这些规则。

## 每轮都交付能检查的结果

下面是拆分示例，不代表这些能力已在你的应用中接好：

| 轮次 | 本轮目标           | 怎么检查                         |
| ---- | ------------------ | -------------------------------- |
| 1    | 明确订单状态和数据 | 创建并读取一条草稿订单           |
| 2    | 完善页面和操作入口 | 列表进入详情，修改后刷新数据仍在 |
| 3    | 区分业务人员与主管 | 两种账号的操作和数据范围符合约定 |
| 4    | 接入审批           | 提交、通过和拒绝后的状态正确     |
| 5    | 接入通知           | 对应申请人收到该订单的审批结果   |
| 6    | 构建并部署         | 在目标环境重走主流程             |

不要只按文件拆成“先写所有接口，再写所有页面”。每轮有一个能够操作或检查的结果，更容易尽早发现理解偏差。

## 给下一轮明确的起点

```text
上一轮订单状态已完成，新增和刷新检查通过。
这次实现业务人员提交订单、主管审批的流程。
保留现有列表和编辑行为；提交后的修改规则按已确认方案执行。
不要同时加入通知，审批流程检查通过后再做。
```

如果发现前一轮有问题，先修正并复查，再继续。否则后续功能会依赖尚未修好的代码。

## 中断后如何接着做

把当前状态留在项目的工作记录中：目标、已确认规则、已完成步骤、实际检查、待解决问题和关键文件路径。继续会话时让 AI Agent 先读这份记录，再核对当前代码。

不要只依赖一段很长的聊天历史，也不要把临时进度全部写成永久规则。长期稳定的约定放到[团队规矩](./team-conventions.md)，某个功能的进度单独保存。

需要一个连续案例时，可以从[订单系统教程](../tutorials/index.md)查看各章节的路线；每一轮仍按[检查 AI Agent 的产出](./reviewing-output.md)确认结果。
