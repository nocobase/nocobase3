# 配置 LLM

LLM 配置分成两层：源码中的 `config.yml` 声明服务和模型，管理后台控制服务是否对当前应用开放。这样开发环境和生产环境可以使用同一套结构，只替换密钥和模型列表。

## 配置流程

1. 在 `config.yml` 的 `ai.llmServices` 中声明服务
2. 用环境变量注入 API Key
3. 重新加载应用配置
4. 进入管理后台的「AI 员工」设置
5. 在「LLM 服务」页签启用需要的模型
6. 在 AI 员工详情中选择默认模型或允许的模型范围

完整示例见[在 config.yml 中配置 LLM](../quick-start/config-llm.md)。

## 为什么还要在后台启用

`config.yml` 描述应用具备哪些 LLM 连接。后台启用开关决定这些服务和模型是否被员工、聊天组件和普通用户使用。

这种分工适合团队协作：

- 开发者负责 provider、环境变量和模型 ID
- 管理员负责日常启用、停用和员工模型选择
- 密钥始终留在服务端，不进入浏览器

## 多模型策略

如果应用同时提供多个模型，可以按任务分工：

- 复杂分析和长文本使用能力更强的模型
- 高频摘要使用成本更低、速度更快的模型
- 需要联网检索的员工只选择支持 web search 的模型

员工的模型限制应当和业务目标一致。没有明确限制时，默认让管理员从已启用模型中选择即可。
