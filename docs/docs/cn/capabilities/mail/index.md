# 邮件

邮件插件让用户把自己的邮箱接入 NocoBase，在应用中阅读、回复和发送邮件。一个用户可以关联多个邮箱，统一查看来信，也可以按账户和文件夹筛选。应用开发者可以把邮件工作区放进客户、项目等业务页面，让沟通和业务记录在同一个地方完成。

## 可以做什么

| 能力         | 说明                                                                                   |
| ------------ | -------------------------------------------------------------------------------------- |
| 连接多个邮箱 | 内置 Gmail、Microsoft 365 和 IMAP/SMTP 服务商，用户分别关联自己的账户                  |
| 阅读和整理   | 搜索邮件、查看会话、标记已读和星标、下载附件，并使用 NocoBase 标签、私有备注和待办标记 |
| 写信和回复   | 富文本正文、附件、抄送、密送、回复、转发和发件别名                                     |
| 复用内容     | 管理账户签名和个人模板，在业务页面中传入模板变量                                       |
| 保存和发送   | 自动保存本地草稿、定时发送，也可以向多个收件人分别发送                                 |
| 同步与追踪   | 后台同步邮箱，查看同步进度、发送结果和失败原因                                         |

如果需求是发送审批结果、验证码或系统提醒，参见[通知](../notification.md)的邮件渠道。邮件插件用于用户关联的邮箱，账户授权、收发信和记录独立于通知渠道。

## 服务商能力差异

三种服务商都随 `@nocobase/app-plugin-mail` 提供。注册 Mail 插件后，在 `config.yml` 中配置需要的服务商实例即可。

| 能力                              | Gmail          | Microsoft 365      | IMAP/SMTP              |
| --------------------------------- | -------------- | ------------------ | ---------------------- |
| 账户接入                          | OAuth          | OAuth              | 用户名和密码           |
| 收信、发信和附件                  | 支持           | 支持               | 支持                   |
| 周期同步                          | 支持           | 支持               | 支持，主要发现新增邮件 |
| 推送触发同步                      | 需配置 Pub/Sub | 需配置公共回调地址 | 不支持                 |
| 本地草稿、签名、模板和定时发送    | 支持           | 支持               | 支持                   |
| 服务商端草稿镜像                  | 支持           | 支持               | 不支持                 |
| 服务商发件别名发现                | 支持           | 支持               | 不支持                 |
| 移动到文件夹                      | 支持           | 支持               | 不支持                 |
| 服务商原生标签                    | 支持           | 不支持             | 不支持                 |
| NocoBase 标签、私有备注和待办标记 | 支持           | 支持               | 支持                   |

IMAP/SMTP 通过新的 UID 范围发现邮件，暂不完整同步其他客户端发生的已读、删除和移动变更，也不支持移入回收站。已发送邮件需要先保存在服务商邮箱中才能同步回来；SMTP 服务不会自动保存副本时，可以配置由插件保存，见[IMAP/SMTP 配置](./configuration.md#imapsmtp)。

## 页面在哪里

插件提供开发页面，用来验证邮件能力和参考页面实现。生产应用的邮件入口由应用开发者通过公开组件接入，插件当前不提供独立的 `/mail` 业务页面。

| 入口                      | 用途                                   |
| ------------------------- | -------------------------------------- |
| `/dev/mail/accounts`      | 关联和管理自己的邮箱、签名、模板和标签 |
| `/dev/mail/center`        | 邮件中心，阅读、整理和发送邮件         |
| `/dev/mail/send`          | 写邮件，选择普通发送或分别发送         |
| `/dev/mail/logs`          | 查看自己的发送、批量发送和同步记录     |
| `/dev/mail/management`    | 有独立权限的全用户邮件管理             |
| `/settings/mail/accounts` | 管理员只读查看所有用户关联的账户       |

这些路径相对于应用挂载位置。例如应用挂载在 `/main` 时，邮件中心地址是 `/main/dev/mail/center`。`/dev/*` 页面只在开发环境中提供，不进入生产构建。

## 和 Agent 一起开发

邮件插件随包提供应用开发 Skill。你可以向应用 Agent 描述邮箱类型、业务页面、使用者和管理范围，由它检查插件配置、接入组件并验证收发信。个人邮件接口会校验账户所有权；全用户邮件管理权限可以操作所有用户的邮件，需要单独决定授予范围。

例如：

> 为客户管理应用接入公司的 IMAP/SMTP 邮箱，让销售关联自己的邮箱，在客户详情中阅读和回复邮件。把当前客户姓名传给邮件模板，提供账户、签名和模板管理入口。普通销售只能操作自己的邮箱，邮件管理员可以查看关联账户。请检查现有插件和 Skill，完成接入并验证。
