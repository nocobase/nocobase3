# 邮件

邮件能力让用户把自己的邮箱接入应用，在同一个工作区阅读邮件、回复客户、管理草稿和发送附件。一个用户可以连接多个账户，统一查看已同步的邮件，也可以按账户和文件夹筛选。

如果需求是发送审批结果、验证码或系统提醒，使用[通知](../notification.md)的邮件渠道。这里的邮件插件面向用户关联的邮箱，负责账户授权、收发信和邮箱同步，两者的配置与发送记录相互独立。

## 邮件插件与内置服务商

`@nocobase/app-plugin-mail` 提供账户、授权、同步、发送、草稿、邮件工作区和操作日志，并内置以下服务商（Provider）：

| 内置服务商    | 负责什么                                             |
| ------------- | ---------------------------------------------------- |
| Gmail         | Gmail OAuth 授权、Gmail API 和推送同步               |
| Microsoft 365 | Microsoft 365 OAuth 授权、Microsoft Graph 和推送同步 |
| IMAP/SMTP     | 使用用户名和密码连接标准 IMAP/SMTP 邮箱              |

应用只需注册 Mail 插件，再在 `config.yml` 的 `mail.providers` 中配置服务商实例。第三方服务商仍可通过扩展插件接入。

## 接入应用

默认应用模板已经注册 Mail，填写[邮件配置](./configuration.md)即可继续关联账户。自定义应用在应用目录中执行：

```bash
pnpm plugin:register mail
pnpm migrate
```

首次启用后执行迁移以创建邮件数据表。自动同步和定时发送需要应用的队列正常运行。

接着为目标用户授予邮件工作区访问权限，配置服务商并重启应用，再按[使用邮件](./usage.md)关联账户、同步和发送一封测试邮件。

也可以把业务要求交给 Coding Agent：

```text
为应用接入 NocoBase 邮件能力，使用公司的 IMAP/SMTP 邮箱。
让用户关联自己的邮箱，在邮件工作区阅读和回复邮件。
在客户详情中复用邮件工作区，并把当前客户记录传入邮件模板变量。
普通用户只能操作自己的邮箱；邮件管理员可以查看账户和操作日志。
为生产页面补充账户、签名和模板管理入口。
```

## 页面与权限

下表是应用内的路由路径。应用挂载在 `/main` 时，访问地址需要带上该前缀，例如 `/main/mail`。

| 入口                                         | 用途                                       | 所需权限                      |
| -------------------------------------------- | ------------------------------------------ | ----------------------------- |
| `/mail`                                      | 当前用户的邮件工作区                       | `page:mail.workspace/access`  |
| `/settings/mail/accounts`                    | 只读查看所有用户已连接的账户               | `page:mail.admin/access`      |
| `/settings/mail/operation-logs`              | 查看所有用户的同步和发送日志               | `page:mail.admin/access`      |
| `/dev/mail/accounts`                         | 开发环境中的个人账户、签名、标签和模板管理 | `page:mail.workspace/access`  |
| `/dev/mail/management`                       | 开发环境中的全用户邮件表格和批量操作       | `page:mail.management/access` |
| `/dev/mail/sync-logs`、`/dev/mail/send-logs` | 开发环境中的个人同步和发送诊断             | `page:mail.workspace/access`  |

`/dev/mail/*` 是开发页面，不进入生产构建。生产应用需要的账户管理入口可以复用插件公开的组件和 API。个人 API 除了校验页面权限，还会校验账户所有权；全用户邮件管理权限能够查看和操作所有用户的邮件，目前没有部门或组织范围隔离，应按实际职责授予。

## 服务商能力差异

| 能力                              | Gmail          | Microsoft 365      | IMAP/SMTP              |
| --------------------------------- | -------------- | ------------------ | ---------------------- |
| 账户接入                          | OAuth          | OAuth              | 用户名和密码           |
| 收信、发信和附件                  | 支持           | 支持               | 支持                   |
| 自动同步                          | 支持           | 支持               | 支持，主要发现新增邮件 |
| 推送触发同步                      | 需配置 Pub/Sub | 需配置公共回调地址 | 不支持                 |
| 本地草稿、签名、模板和定时发送    | 支持           | 支持               | 支持                   |
| 服务商端草稿镜像                  | 支持           | 支持               | 不支持                 |
| 服务商发件别名发现                | 支持           | 支持               | 不支持                 |
| 移动到文件夹                      | 支持           | 支持               | 不支持                 |
| 服务商原生标签能力                | 支持           | 不支持             | 不支持                 |
| NocoBase 标签、私有备注和待办标记 | 支持           | 支持               | 支持                   |

IMAP/SMTP 当前通过新的 UID 范围发现邮件，不保证完整回传在其他邮件客户端发生的已读、删除和移动变更。如果 SMTP 服务不会自动把已发邮件保存到「已发送」，邮件插件也不会主动追加副本；只有 IMAP 中出现该邮件后，才能同步到本地。
