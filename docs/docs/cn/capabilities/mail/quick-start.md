# 快速开始

本教程以公司的 IMAP/SMTP 邮箱为例，先在开发环境中完成一次收发信，再将邮件入口接入业务页面。使用 Gmail 或 Microsoft 365 OAuth 的应用可以替换服务商配置，其余验证步骤相同。

## 前置条件

- 已有一个能够通过 `pnpm dev` 启动的 NocoBase 3 应用。
- 已准备邮箱地址、登录用户名、密码或邮箱授权码，以及 IMAP/SMTP 服务器地址和端口。
- 当前用户拥有邮件工作区访问权限：`page:mail.workspace/access`。
- 应用数据库和后台队列能够正常运行。

默认应用模板已在 Server 和 Client 注册 Mail 插件。自定义应用尚未注册时，在应用根目录执行：

```bash
pnpm plugin:register mail
pnpm migrate
```

首次启用需要完成迁移，创建邮件数据表。已有应用也应确认迁移已执行。

## 第一步：配置服务商

在应用根目录的 `config.yml` 中加入以下配置，将服务器地址替换为邮箱服务商提供的值：

```yaml
mail:
  providers:
    company-mail:
      type: imap-smtp
      imap:
        host: imap.example.com
        port: 993
        secure: true
      smtp:
        host: smtp.example.com
        port: 465
        secure: true
```

这里配置的是全应用共用的服务器信息。每个用户的邮箱密码在关联账户时填写。修改配置后重启应用。

上例使用直接 TLS 连接。如果服务商要求 STARTTLS 或需要由客户端保存已发送副本，参见[配置邮件](./configuration.md)。Gmail 和 Microsoft 365 OAuth 接入也在该页说明。

## 第二步：关联邮箱

打开 `/dev/mail/accounts` 的个人账户页面，点击「关联账户」：

1. 选择刚配置的 `company-mail` 服务商实例。
2. 设置首次同步起始日期；首次验证可以选择最近几天，缩短历史导入时间。
3. 填写邮箱地址、用户名和密码。服务商要求授权码或应用专用密码时，填写该值。
4. 完成关联，确认账户状态正常。

插件会验证 IMAP 和 SMTP 连接后再保存凭据。使用 OAuth 服务商时，第三步会改为跳转到服务商完成授权。

文档中的路径均相对于应用挂载位置。如果应用挂载在 `/main`，这里访问的是 `/main/dev/mail/accounts`。

## 第三步：同步并阅读邮件

打开 `/dev/mail/center`，发起同步。在 `/dev/mail/logs/sync` 查看任务进度，回到邮件中心确认能看到起始日期范围内的邮件，并打开一封检查正文和附件。

历史导入按批次在后台运行，期间也会同步新增变更。邮件较多时，可以先阅读已经导入的内容。刷新列表只重新读取本地数据，需要从服务商获取新邮件时使用同步操作。

## 第四步：发送一封测试邮件

在邮件中心点击写邮件，选择发件地址，向自己可以查收的另一个邮箱发送测试邮件。然后检查：

- `/dev/mail/logs/send` 中有对应的发送记录，状态为 `accepted`。
- 收件邮箱实际收到邮件，正文和附件正确。
- 同步后能在发件账户的已发送文件夹看到邮件；IMAP/SMTP 需要服务端或插件保存了已发送副本。

`accepted` 表示服务商接受了提交，实际查收才能确认这次测试的投递结果。遇到等待、失败或结果不确定，参见[管理与诊断](./management.md)。

## 第五步：接入业务页面

开发页面用于验证能力，生产应用需要自己的入口。把下面的需求交给应用 Agent：

> 邮件账户已经能同步和发送。请参考当前插件的邮件中心，为应用增加生产可用的邮件页面和个人账户管理入口，复用公开组件。检查页面权限、OAuth 授权完成后的返回位置，并验证生产构建中的关联账户、阅读、回复、草稿和发送记录。

具体组件和验收要点见[应用开发](./development.md)。
