# 管理与诊断

邮件管理分为个人账户管理、管理员账户总览和全用户邮件管理。个人日志记录自己的收发信结果，开发者可以用它定位配置、同步和投递问题。

以下路径均相对于应用挂载位置。`/dev/*` 页面只在开发环境提供；生产应用需要的管理和诊断入口由应用开发者接入。

## 账户管理

在 `/dev/mail/accounts` 关联、停用、启用或移除自己的账户，也可以管理签名、模板和标签。

停用后，该账户不能发送或同步。移除会清理应用中的账户、授权信息和本地同步数据，不会删除服务商邮箱里的邮件。账户需要重新授权时，重新关联并完成授权，再恢复同步。

管理员在「设置 / 邮件 / 账户」（`/settings/mail/accounts`）只读查看所有用户已关联的账户。该页面用于了解接入情况，个人账户的修改仍通过所属用户的管理入口完成。

## 权限范围

| 权限                          | 允许访问的能力                                   |
| ----------------------------- | ------------------------------------------------ |
| `page:mail.workspace/access`  | 个人账户、邮件中心、写信及个人日志               |
| `page:mail.admin/access`      | 所有用户的账户总览，以及设置类账户和操作日志 API |
| `page:mail.management/access` | 全用户邮件查询和批量操作                         |

个人 API 除了校验页面权限，还会校验账户所有权。全用户邮件管理权限可以查看和操作所有用户的邮件，目前没有部门或组织范围隔离，应按实际职责授予。

`/dev/mail/management` 提供全用户邮件表格、筛选和批量操作。移动到文件夹在个人邮件中心操作。

## 同步记录

打开 `/dev/mail/logs/sync`，按账户和状态查看同步记录。日志展示当前阶段、处理的邮件数和批次数，帮助判断任务是在导入历史、处理变更还是恢复进度。

| 状态        | 含义                                     |
| ----------- | ---------------------------------------- |
| `pending`   | 等待后台执行                             |
| `running`   | 正在同步                                 |
| `completed` | 本次同步已完成                           |
| `partial`   | 同步结束，但仍有邮件正文待加载或处理失败 |
| `failed`    | 同步失败，需要查看错误原因               |
| `cancelled` | 同步已取消                               |

账户所有者可以取消活动同步，或重试失败、已取消的同步任务。`partial` 记录中的待处理数量是任务结束时的快照；之后补齐正文不会改写该次日志，后续同步会更新统计。

首次同步根据起始日期分批导入，没有累计邮件数量上限。服务重启后，后台会在租约或投递等待期结束后恢复中断的任务。服务商同步游标失效时，会重新扫描账户配置的历史范围，保留已有本地邮件和用户元数据；已经不在服务商变更历史中的删除，不保证能在这次重扫中补齐。

## 发送记录

在 `/dev/mail/logs/send` 查看普通发送和定时发送记录，在 `/dev/mail/logs/bulk` 查看分别发送的批次及收件人结果。账户和日志表格支持分页、跳转页码，并可选择每页 20、50 或 100 条记录。

| 状态         | 含义                                       |
| ------------ | ------------------------------------------ |
| `pending`    | 等待执行，包括尚未到期的定时发送           |
| `submitting` | 正在向服务商提交                           |
| `accepted`   | 服务商已接受提交，不代表收件人已收到或阅读 |
| `failed`     | 提交失败，需要处理错误原因                 |
| `unknown`    | 无法确认服务商是否已接受，邮件可能已经发出 |

结果为 `unknown` 时，先确认服务商端的结果，直接重发可能造成重复邮件。批量发送可以展开查看每个收件人的结果，对失败项重试；尚未被后台任务领取的发送可以取消。

SMTP 可能只接受部分收件人。此时记录仍为 `accepted`，并显示部分投递及被拒绝的收件人，应只向被拒绝的地址重新发送。保存已发送副本失败也不会把已经接受的发送改为失败，修复归档配置后再处理副本，避免重复发信。

## 常见问题

### 看不到邮件页面

先检查运行环境和应用挂载前缀。插件提供的邮件中心在 `/dev/mail/center`，生产构建不包含开发页面；应用自己的邮件入口需要单独接入。再确认 Client 插件已注册，当前角色拥有对应页面权限。

### 服务商显示不可用

确认 Server 已注册 Mail 插件，`mail.providers` 中存在对应类型且已启用的实例，并填写了必要凭据或端点。Gmail、Microsoft 365 和 IMAP/SMTP 已内置，无需分别注册服务商插件。配置修改后需要重启应用。

### OAuth 回调失败

检查公共 origin、应用挂载路径和回调配置组成的完整地址，是否与服务商登记的地址一致，尤其是主机名、端口和 `/main` 等前缀。参见[OAuth 回调地址](./configuration.md#oauth-回调地址)。

### 账户提示需要重新授权

`reauthorizationRequired` 表示授权已不能继续使用。重新关联账户完成授权后，再重试同步。账户停用或服务商实例被禁用，也会阻止发送和同步。

### 同步一直等待

确认数据库迁移已完成、队列和邮件运行时已启动，再查看服务端日志。首次同步按批次执行，重启后的任务恢复也需要等待后台检查，不会通过刷新页面立即完成。

### 历史邮件或正文不完整

先检查账户的首次同步起始日期和任务进度。历史导入没有累计数量上限，但只覆盖配置的日期范围。

IMAP 中超过 16 MiB 的邮件会先保存基本信息和附件元数据，正文标记为待加载；单封邮件解析失败也会保留记录。可以在邮件详情中加载或重试正文，再查看后续同步结果。

### 其他客户端修改的状态没有同步

先确认增量同步已完成。IMAP/SMTP 暂不完整同步外部已读、删除和移动变更，具体见[服务商能力差异](./index.md#服务商能力差异)。

### 发信成功，但已发送文件夹里没有

服务商接受发送后，插件会发起邮箱刷新，但服务商保存邮件可能有延迟。IMAP/SMTP 默认由服务端保存副本；服务端没有该功能时，按[IMAP/SMTP 配置](./configuration.md#imapsmtp)启用客户端保存，并确认目标文件夹存在。日志中的 `IMAP_SENT_COPY_FAILED` 表示副本保存失败，不表示邮件未发出。
