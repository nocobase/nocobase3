# 使用邮件

开始前，确认应用已经完成[邮件配置](./configuration.md)，并为当前用户授予 `page:mail.workspace/access`。以下路径均相对于应用挂载位置，例如应用前缀是 `/main` 时，邮件工作区地址为 `/main/mail`。

## 关联邮箱

开发环境中，打开 `/dev/mail/accounts` 的「邮件账户」页面，点击「关联账户」：

1. 选择已经配置的 Gmail、Microsoft 365 或 IMAP/SMTP 服务商。
2. 按需设置首次同步起始日期，限制导入的历史邮件范围。
3. Gmail 和 Microsoft 365 跳转到服务商完成授权；IMAP/SMTP 填写邮箱地址、用户名和密码。
4. 返回后确认账户状态为「正常」，再开始同步并到 `/mail` 查看结果。

自动同步间隔统一通过 config 中的 `mail.automaticSyncIntervalMs` 配置，对新账户和已有账户生效。账户列表可以停用、启用或移除账户。停用的账户不能发送或同步。移除会清理应用中的账户、授权信息和本地同步数据，不会删除服务商邮箱里的邮件。

这些账户管理页面属于开发工具。生产应用可以复用 `@nocobase/app-plugin-mail/client/components` 中的 `MailAccountConnector` 等公开组件和账户 API，提供适合业务的入口。

## 阅读和整理

`/mail` 默认展示当前用户全部账户的已同步邮件，并标明来源账户。可以搜索邮件，按未读、星标或 NocoBase 标签筛选；选择一个账户后可以按服务商文件夹查看。

「同步全部邮箱」会为所有正常且支持增量同步的账户发起同步；选择某个账户后，同步范围缩小到该邮箱。刷新页面上的数据与向服务商同步邮件是两个步骤，如果新邮件尚未导入，应检查同步任务。

打开邮件时，如果服务商提供稳定的会话标识，会显示完整会话；没有会话标识的邮件单独打开，不会仅因主题相同而合并。

可以标记已读或未读、加星标、下载附件，并按服务商支持的能力移动、归档或删除邮件。永久删除不可撤销。NocoBase 标签、私有备注和待办标记保存在应用中，不会变成服务商邮箱里的标签或任务，重新同步也会保留。

## 写信、草稿和定时发送

点击「写邮件」，选择发件账户和地址，填写收件人、主题和正文。支持抄送、密送、富文本、附件、回复和转发。可选择账户签名、切换到其他签名，或不使用签名。

草稿优先保存在本地数据库，并自动保存编辑内容；页面重新加载后可恢复未完成的编辑。Gmail 和 Microsoft 365 还支持服务商端草稿镜像。IMAP/SMTP 可以使用本地草稿，但不会同步为服务商端草稿。遇到远端草稿冲突时，先查看差异，再选择保留的版本。

需要稍后发送时，打开「定时发送」并选择时间。任务持久化后由后台队列执行，不要求浏览器保持打开；到期仍需账户可用、服务商可连接且队列正常运行。

开发环境的 `/dev/mail/bulk-send` 提供批量发送，最多支持 100 人，为每个收件人创建独立提交记录，并提供收件人预览和逐项结果。部分失败时应只处理失败项。

## 签名、模板与业务记录

开发环境的账户页提供签名、模板和标签管理。每个账户可以有多个命名签名和一个默认签名，账户内各发件地址共用。模板属于当前用户，可复用主题和正文；应用模板会替换现有内容。

在业务记录页面复用 `MailWorkspacePage` 时，可以通过 `templateVariables` 传入当前记录：

```tsx
import { MailWorkspacePage } from '@nocobase/app-plugin-mail/client';

<MailWorkspacePage
  templateVariables={{ record: { customer: { name: 'Alex' } } }}
/>;
```

模板中的 `{{record.customer.name}}` 会在应用模板时替换成 `Alex`。没有匹配数据的变量会保留原样，发送前需要检查。组件应放在应用客户端的服务和权限上下文中；默认邮件工作区不会自动知道当前客户记录。

## 查看结果

管理员在「设置 / 邮件 / 操作日志」查看所有用户的同步和发送记录，可以按账户、状态、时间等筛选。个人诊断页面为 `/dev/mail/sync-logs` 和 `/dev/mail/send-logs`。

同步状态包括等待中、进行中、已完成、失败和已取消。日志显示当前阶段及处理的邮件数、批次数；账户所有者可以取消活动同步，或重试失败、已取消的同步任务。

发送记录的含义如下：

| 状态         | 含义                                         |
| ------------ | -------------------------------------------- |
| `pending`    | 等待执行，包括尚未到期的定时发送             |
| `submitting` | 正在向服务商提交                             |
| `accepted`   | 服务商已接受提交，不代表收件人已收到或阅读   |
| `failed`     | 提交失败，需要查看错误并处理原因             |
| `unknown`    | 无法确认服务商是否已经接受，邮件可能已经发出 |

如果发送结果是 `unknown`，先确认服务商端的结果，再决定下一步；直接重新发送可能重复发信。应用通过 `MailService.sendMessage()` 或 `POST /api/mail/messages/send` 发送时，必须为同一次业务发送复用稳定的 `idempotencyKey`。相同键用于不同内容会被拒绝，不要因请求超时就换新键重发。

## 常见问题

### 服务商显示不可用

确认服务端注册了对应的服务商插件，`mail.providers` 中存在同类型且已启用的实例，并已填写必要的凭据或端点。仅注册插件不会完成配置。

### OAuth 回调失败

检查公共 origin、应用挂载路径和回调配置拼成的最终地址，与服务商登记的地址是否一致。特别检查主机名、端口和 `/main` 等应用前缀，参见[配置邮件](./configuration.md)。

### 账户提示需要重新授权

`reauthorizationRequired` 表示授权已不能继续使用。重新关联账户完成授权后，再重试同步。停用或撤销的账户同样不能发送和同步。

### 同步一直等待，或历史邮件不完整

先检查迁移是否完成、后台队列是否运行以及服务端日志。首次同步按批次执行，起始日期和数量限制会影响历史导入范围；同步不是一次请求下载整个邮箱。服务商同步游标失效时，下次同步会重新开始首次同步。

### 在其他邮件客户端修改后，本地状态没有变化

先确认增量同步已完成。IMAP/SMTP 当前不保证完整同步外部已读、删除和移动变更，也不主动追加「已发送」副本；具体限制见[服务商能力差异](./index.md#服务商能力差异)。
