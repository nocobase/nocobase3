# 使用邮件

完成[快速开始](./quick-start.md)后，可以在开发环境的 `/dev/mail/center` 使用邮件中心。生产应用的入口由应用开发者接入，页面名称和位置以应用为准。以下操作都针对当前用户关联的邮箱。

## 阅读邮件

邮件中心统一展示多个账户的已同步邮件，并标明来源账户。选择一个账户后，可以按服务商文件夹查看；也可以搜索邮件，按未读、星标或 NocoBase 标签筛选。

桌面端将邮箱导航、邮件列表和会话详情并排展示。邮件列表每页显示 50 封，底部可以切换上一页和下一页；切换筛选条件后回到第一页。

打开邮件时，如果服务商提供稳定的会话标识，会显示对应会话；没有会话标识的邮件单独打开，不会仅因主题相同而合并。正常账户打开邮件后，会将已加载的非草稿会话邮件标记为已读。如果状态更新失败，正文仍可阅读，页面会提示错误。

邮件正文中的附件可以下载。部分大邮件或解析失败的邮件可能先显示基本信息，并提示加载或重试正文；这类邮件不会阻塞其他邮件的同步。

## 同步邮箱

「同步全部邮箱」会对正常且支持增量同步的账户发起同步。选中一个账户后，同步范围缩小到该邮箱。

刷新列表与同步邮箱是两个操作：刷新读取应用已经保存的数据，同步从服务商获取邮件变更。应用也会按统一配置周期自动同步，默认每 5 分钟一次，见[同步配置](./configuration.md#同步配置)。

首次同步按照关联时设置的起始日期导入历史邮件，没有累计封数上限。历史导入和增量同步交替推进；服务重启后，后台会恢复未完成的任务。进度和异常可以在[同步记录](./management.md#同步记录)中查看。

## 整理邮件

可以标记已读或未读、加星标，并根据服务商支持的能力移动、归档或删除邮件。IMAP/SMTP 不支持移动到文件夹和普通删除，需要移入回收站时请使用服务商客户端；永久删除会直接删除服务商邮件，操作前应确认内容。

NocoBase 标签、私有备注和待办标记保存在应用中，重新同步后仍会保留。它们不会自动变成服务商邮箱中的标签、备注或任务。

## 写信、回复和转发

点击写邮件，从发件地址中选择邮箱或可用别名，填写收件人、主题和正文。普通发送支持抄送、密送、富文本和附件。也可以从会话中回复或转发。

转发时，原邮件与本次补充说明分开呈现，保留原邮件的格式；可以在原邮件前编写自己的说明。

### 签名和模板

每个账户可以保存多个命名签名，并选择一个默认签名。该账户的不同发件地址共用签名，写信时可以切换，也可以不使用签名。

模板属于当前用户，可复用主题和正文。在开发环境的 `/dev/mail/accounts` 管理签名、模板和标签。应用模板会替换当前主题和正文，使用前应确认要保留的内容。

业务页面可以向模板传入当前记录。例如模板中的 `{{record.customer.name}}` 可以替换成客户姓名。没有匹配数据的变量会保留原样，发送前需要检查；默认邮件中心不会自动获取业务记录，接入方式见[应用开发](./development.md#传入业务记录)。

### 草稿

编辑内容会自动保存到本地数据库，页面重新加载后可以恢复未完成的编辑。Gmail 和 Microsoft 365 还支持服务商端草稿镜像；IMAP/SMTP 使用本地草稿，不同步为服务商端草稿。

遇到远端草稿冲突时，先查看差异，再选择保留的版本。关闭仍有未保存修改的写信窗口时，按页面提示处理修改。

### 定时发送

打开定时发送并选择时间。任务保存后由后台队列执行，不要求浏览器保持打开；到期时仍需账户正常、服务商可连接且队列运行。

### 分别发送

开发环境的 `/dev/mail/send` 在同一个写信界面中提供普通发送和分别发送。分别发送会为每个收件人创建独立的提交记录，收件地址去重后最多支持 100 人，使用前需要清空抄送和密送。

在 `/dev/mail/logs/bulk` 查看批次和每个收件人的结果。部分失败时只处理失败项，避免再次向已成功的收件人发信。

## 查看发送结果

普通发送、定时发送和分别发送都会留下提交记录。`accepted` 只表示服务商接受提交，结果为 `unknown` 时则可能已经发出，应先确认服务商端结果。

完整的状态说明、部分投递处理和排查路径见[管理与诊断](./management.md#发送记录)。
