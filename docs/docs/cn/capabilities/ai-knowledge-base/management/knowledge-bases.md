# 配置和管理知识库

在 NocoBase 中，知识库保存原始文档、分段内容和向量检索所需的元数据。知识库维护和 NocoBase 2.x 的使用方式基本一致，区别主要在于 NocoBase 3 的插件包、配置入口和应用侧 Registry 组织方式。

## 打开管理页面

进入 AI 设置中的「Knowledge Base」页签。这里可以查看知识库、进入详情页、上传文档并运行检索测试。

## 知识库类型

创建知识库时需要选择类型：

- `LOCAL`：由当前 NocoBase 应用保存文件、分段并写入向量，适合新建知识库
- `READONLY`：读取已经存在的向量存储，不在当前知识库中写入
- `EXTERNAL`：由外部 provider 提供知识库能力，是否可用取决于应用安装的扩展

大部分场景用 `LOCAL` 就够了。

## 创建 LOCAL 知识库

点击「Add new」，填写以下配置：

| 配置项          | 说明                                   |
| --------------- | -------------------------------------- |
| Name            | 管理页面显示的名称                     |
| Key             | 稳定的业务标识，创建后不要随意修改     |
| Type            | 选择 `LOCAL`                           |
| Disk            | 保存源文件和分段 shard 的文件存储 disk |
| Vector database | 选择已配置的向量数据库                 |
| LLM service     | 选择提供 Embedding 的 LLM service      |
| Embedding model | 选择对应的向量模型                     |
| Segmentation    | 是否自动把文档分成多个段落             |
| Chunk size      | 单个分段的目标大小，默认 6000          |
| Chunk overlap   | 相邻分段的重叠大小，默认 1200          |

保存前确认向量数据库和 Embedding 模型已经启用。缺少任意一项时，文档可以保存，但后续向量化通常无法完成。

## 上传文档

进入知识库详情页，点击「Upload」。单次只上传一个文件，服务端支持 `.pdf`、`.pptx`、`.doc`、`.docx`、`.xls`、`.xlsx`、`.xlsm`、`.txt`、`.md`、`.json` 和 `.csv`，文件大小上限为 100 MiB。

上传流程分为两段：

1. 同步保存源文件和文档记录
2. 通过 `default` queue 异步完成解析、分段、Embedding 和向量保存

所以，上传接口返回成功后，文档仍可能处于处理中。进入文档详情或刷新列表，直到状态为 `SUCCESS` 或 `ERROR`。

## 文档状态和重试

- `PENDING`：已创建，等待处理
- `PROCESSING`：正在解析、分段或向量化
- `SUCCESS`：处理完成，可以参与检索
- `ERROR`：处理失败，需要查看错误原因并重试

遇到 `ERROR` 时，先检查文件格式、文本是否可解析、Embedding service、向量数据库和队列。不要只重复点击上传，否则会留下重复文档。

## 维护分段

打开文档的分段列表，可以查看分段内容、启用或停用分段、编辑内容和维护 related questions。修改分段内容需要使用当前的 `contentHash`，防止覆盖其他管理员刚刚保存的版本。

编辑、启用、停用和删除分段会触发重新向量化。批量重生成分段前，先确认影响范围和队列容量。

## 删除影响

删除知识库或文档前先确认备份和影响范围。知识库删除会影响其文件、分段和向量；删除向量数据库前，还要确认没有知识库引用它，也没有未完成的队列任务指向它。

:::warning 注意

管理页面的按钮状态不是服务端授权。生产环境必须使用有权限的账号，并确保应用代理或后端路由独立完成认证和授权。

:::
