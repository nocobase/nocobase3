# 主题

在 NocoBase 3 中，**主题（Theme）不是插件，代码就在你的项目里，可以直接修改**。你可以调整配色、字体、字号、间距、圆角和阴影，让业务系统符合品牌风格，或让表格、表单更适合日常办公。

这些调整不需要开发或安装插件。你可以把需求交给 coding agent，由它修改项目中的主题文件，再通过实际页面检查效果。你需要明确想要的外观、了解改动会影响哪些地方，不必先熟悉每个 CSS 变量。

下面的路径都相对于你创建的应用项目根目录，以默认应用模板为例。

## 内置了哪些主题

当前内置两套主题预设：

| 主题 | ID        | 外观特点                                                                 | 文件                              |
| ---- | --------- | ------------------------------------------------------------------------ | --------------------------------- |
| 默认 | `default` | 中性配色，常规间距和圆角，适合作为定制起点                               | `client/theme/themes/default.css` |
| 紧凑 | `compact` | 和默认主题使用相同配色，通过更小的间距、部分文字的行高和圆角提高信息密度 | `client/theme/themes/compact.css` |

在应用的「外观」面板中，可以选择主题，也可以选择「浅色」「深色」或「跟随系统」。**主题和颜色模式是两个独立选项**：默认主题和紧凑主题都支持浅色、深色显示；新增主题也应该同时提供这两种配色。

<!-- 需要一张「外观」面板截图，展示浅色、深色、跟随系统选项，以及默认、紧凑两张主题卡片 -->

主题选择保存在当前浏览器中，并按应用隔离。刷新后会恢复选择，但不会随账号自动同步到其他设备。修改主题源码后，使用这套主题的人会看到新的外观；在「外观」面板中切换主题，只改变当前浏览器的选择。

## 主题由哪些文件组成

一套主题主要包含三部分：CSS 定义外观，主题列表决定可选项，语言文件提供显示名称。

| 文件                                | 作用                               | 什么时候需要修改         |
| ----------------------------------- | ---------------------------------- | ------------------------ |
| `client/theme/themes/<主题 ID>.css` | 定义浅色、深色的颜色和其他样式变量 | 修改外观，新增或删除主题 |
| `client/theme/theme-presets.ts`     | 登记主题 ID 和名称的翻译键         | 新增或删除主题           |
| `client/styles.css`                 | 导入各套主题的 CSS                 | 新增或删除主题           |
| `client/locales/zh-CN.ts`           | 定义中文主题名称                   | 新增、删除或改名         |
| `client/locales/en-US.ts`           | 定义英文主题名称                   | 新增、删除或改名         |

如果项目增加了其他语言，也要同步维护对应语言文件。普通主题定制不需要修改 `client/theme/theme-provider.tsx`、`client/theme/theme-settings.tsx` 或业务组件。

## 修改现有主题

默认从修改现有主题开始。比如，希望保留紧凑布局，只调整按钮主色和圆角，可以让 coding agent 执行：

```text
请先阅读项目中的 skills/nocobase-app-development/references/themes.md
和 theme-tokens.md，再修改 compact 主题：

- 将主色改为蓝色，并分别调整浅色和深色模式下的配色
- 保留当前字体、字号和紧凑间距，略微增大圆角
- 检查按钮文字、侧边栏选中项和键盘焦点是否清晰
- 保留 compact 这个 ID，不修改默认主题和业务组件

完成后列出修改的文件，并在实际表格、表单和弹窗中验证效果。
```

这类改动通常只涉及 `client/theme/themes/compact.css`。其中的 CSS 变量也叫 **主题 token**，组件通过这些变量使用统一样式。常见的调整有：

| 想调整什么           | 主要变量                                                      | 需要一起考虑什么                                           |
| -------------------- | ------------------------------------------------------------- | ---------------------------------------------------------- |
| 主色                 | `--primary`、`--primary-foreground`                           | 主色背景和其上的文字要有足够对比度                         |
| 页面、卡片和文字颜色 | `--background`、`--foreground`、`--card`、`--card-foreground` | 背景与文字成对调整                                         |
| 侧边栏               | `--sidebar`、`--sidebar-foreground`、`--sidebar-primary` 等   | 选中项、悬停项和普通文字都要清楚                           |
| 字体                 | `--font-sans`、`--font-heading`、`--font-mono`                | 中文回退字体，以及新增字体的资源加载                       |
| 字号和行高           | `--text-sm`、`--text-sm--line-height` 等                      | 文字不能被按钮、输入框或表格行裁切                         |
| 间距和尺寸           | `--spacing`                                                   | 会一起影响使用对应样式类的内边距、控件尺寸、图标和导航宽度 |
| 圆角                 | `--radius`                                                    | 多种圆角尺寸由它派生，但固定圆角不一定跟随                 |
| 阴影                 | `--shadow-sm`、`--shadow-md` 等                               | 弹窗和卡片的层次，以及深色背景上的效果                     |

完整变量说明可以让 coding agent 阅读项目中的 `skills/nocobase-app-development/references/theme-tokens.md`。不需要为一次换色新增变量，也不需要逐个修改按钮或页面样式。

每个主题文件分为基础规则和深色规则。基础规则定义全部变量；深色规则重新定义全部颜色，字体、间距等非颜色变量默认沿用基础规则。修改配色时，两部分都要检查。

如果只是把「紧凑」改名为「高密度」，修改语言文件中的 `appearance.themes.compact` 即可，保留 `compact` 这个 ID。ID 用来识别主题，显示名称可以单独调整。

## 新增一个主题

如果希望保留内置主题，同时提供一套品牌外观，可以新增主题。比如，增加一套名为「森林」、ID 为 `forest` 的绿色主题。

### 第一步：复制并调整主题 CSS

把 `client/theme/themes/default.css` 复制为 `client/theme/themes/forest.css`。保留完整的变量定义，再调整颜色、字体、圆角等值。

复制后，需要将基础规则的选择器改为：

```css
:root[data-theme='forest'],
.theme-preview[data-theme='forest'] {
  /* 保留复制过来的全部变量，在这里调整浅色配色和其他样式 */
}
```

深色规则的选择器改为：

```css
:root.dark[data-theme='forest'],
:root.dark .theme-preview[data-theme='forest'] {
  /* 保留复制过来的全部颜色变量，在这里调整深色配色 */
}
```

这两段只展示选择器结构，不能代替完整主题文件。复制时要移除默认主题中的裸 `:root` 和 `:root.dark` 选择器，避免新主题覆盖其他主题。`.theme-preview` 让「外观」面板中的预览卡片使用同一套配色。

### 第二步：导入样式并加入主题列表

在 `client/styles.css` 中现有主题导入之后添加：

```css
@import './theme/themes/forest.css';
```

在 `client/theme/theme-presets.ts` 的 `themePresets` 数组中追加新主题，保留其他导出：

```ts
export const themePresets = [
  { id: 'default', labelKey: 'appearance.themes.default' },
  { id: 'compact', labelKey: 'appearance.themes.compact' },
  { id: 'forest', labelKey: 'appearance.themes.forest' },
] as const;
```

保留 `default` 在第一位，它也是无法识别已保存主题时的回退主题。「外观」面板会自动读取这个列表，不需要另外编写主题切换界面。

### 第三步：添加显示名称

在 `client/locales/zh-CN.ts` 的 `appearance.themes` 中添加中文名称：

```ts
themes: { default: '默认', compact: '紧凑', forest: '森林' },
```

在 `client/locales/en-US.ts` 的同一位置添加英文名称：

```ts
themes: { default: 'Default', compact: 'Compact', forest: 'Forest' },
```

至此，可以在「外观」面板选择「森林」，分别检查浅色和深色效果。预览卡片主要展示配色，字体、间距和页面布局需要打开实际业务页面确认。

<!-- 需要一张新增「森林」后「外观」面板的截图，并配一组实际业务页面的浅色、深色效果图 -->

你也可以把以上步骤一起交给 coding agent：

```text
请按项目中的主题开发说明，新增 forest 主题，中文名「森林」，英文名 Forest。
以 default 为基础，使用绿色主色，保留当前字体和间距，提供浅色和深色配色。
保留已有主题，将新主题加入「外观」面板，并补齐所有现有语言的名称。
请列出新增和修改的文件，检查切换、刷新恢复和实际业务页面的显示效果。
```

## 删除一个主题

删除主题需要同时清理样式、列表和名称。比如，删除上面新增的 `forest`：

1. 从 `client/theme/theme-presets.ts` 的 `themePresets` 数组中移除 `forest`
2. 从 `client/styles.css` 中移除 `forest.css` 的导入
3. 删除 `client/theme/themes/forest.css`
4. 从各语言文件的 `appearance.themes` 中删除 `forest` 名称

不要只删除 CSS 文件，否则样式导入会指向不存在的文件；只移除主题列表项，也会留下不再使用的样式和翻译。

当前浏览器如果曾选择被删除的主题，刷新应用后会回退到默认主题，不需要手动清理浏览器存储。保留 `default` 及其第一项位置；如果不喜欢默认外观，直接修改 `default.css` 即可。

可以这样交给 coding agent：

```text
请删除 forest 主题，清理主题列表、CSS 导入、CSS 文件和所有语言的名称。
保留 default 作为回退主题。验证删除前已选中 forest 的浏览器在刷新后
能回到默认主题，并确认其余主题仍可正常切换。
```

## 修改后检查什么

让 coding agent 汇报修改文件后，可以对照下面的范围检查：

| 操作               | 预期改动                                                                      |
| ------------------ | ----------------------------------------------------------------------------- |
| 调整已有主题的外观 | 对应主题 CSS；引入新字体时还会涉及字体资源及加载代码                          |
| 修改显示名称       | 各语言文件中的对应名称                                                        |
| 新增主题           | 新 CSS 文件、`client/styles.css`、`client/theme/theme-presets.ts`、各语言文件 |
| 删除主题           | 删除 CSS 文件，同时清理样式导入、主题列表和各语言名称                         |

验收时，打开有真实内容的表格、表单和弹窗，检查以下内容：

- 分别切换浅色、深色和跟随系统，确认文字、按钮、选中项和焦点清晰可见
- 检查长文本、中文、数字和代码，以及窄屏下的布局，确认文字不被裁切、控件便于操作
- 切换到其他主题，确认它们没有被本次改动覆盖；刷新后确认选择能够恢复
- 新增主题时检查名称和预览卡片；删除主题时检查旧选择的回退效果
- 让 coding agent 运行项目现有的主题相关测试和检查命令，并确认构建通过

主题变量只影响使用这些变量的样式。图片、iframe、第三方独立样式，以及写死了颜色或尺寸的自定义组件，不会自动跟随主题。如果某个区域没有变化，可以让 coding agent 先检查它是否使用了主题变量，再判断是否需要单独调整该组件。
