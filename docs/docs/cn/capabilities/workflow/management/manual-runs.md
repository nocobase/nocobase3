# 手动运行工作流

手动运行允许已登录且可访问工作流管理页面的用户，直接执行选中的工作流版本。它适合受控验证或明确的运营操作，不替代应用开发者把流程接入真实业务事件。

## 什么时候使用手动运行

典型用途包括：

- 新版本部署后，用可识别的测试数据验证路径；
- 业务明确允许由管理员发起一次处理；
- 开发者完成故障修复后，授权管理员执行一次新的业务操作。

手动运行不是无副作用预览，也不应被当作任意重试按钮。

## 运行前检查

提交前确认：

1. 工作流标题和说明与目标业务一致；
2. 当前查看的是预期版本，包括历史或未启用版本；
3. 输入对应正确的业务记录；
4. 本次运行是否会写库、发送消息、扣减库存或调用外部系统；
5. 是否已经存在同一业务操作的运行记录；
6. 在生产环境执行是否获得授权。

系统会为手动运行生成调用标识，但这不能保证业务写入或外部调用不会重复。页面结果不明确时先查看执行记录，不要立即再次提交。

## 填写输入并提交

在工作流详情页打开“更多操作 → 手动运行”。如果开发者为该工作流提供了自定义输入表单，页面会显示它；否则根据该版本的输入 Schema 生成默认表单：

- 布尔值显示为勾选项；
- 数字和整数使用数值输入；
- 字符串使用文本输入；
- 字段标题和说明由应用开发者定义。

默认表单只支持顶层的简单字段。需要复杂对象或数组输入时，请开发者提供自定义输入表单，或通过应用的业务入口触发；不要把 JSON 文本填入普通文本框并期望它被自动解析。

提交后，页面会进入本次执行详情。输入无效、缺少必填字段或包含未声明字段时，服务端会拒绝运行。

也可以明确授权 Agent 在开发或测试环境操作：

```text
请在<开发 / 测试>环境中，用输入 <输入内容> 手动运行<工作流的业务名称或目录>的<目标版本>一次。
完成后报告运行 ID、实际使用的版本、最终状态和各节点结果，并核对预期业务数据。
```

验收时确认：实际环境、版本和输入与请求一致，运行已进入终态，实际路径及业务数据符合预期。手动运行不会自动启用该版本。

## 查看提交结果

工作流由队列异步执行，进入执行详情时可能仍显示“排队中”或“运行中”。继续观察直到进入终态：成功、失败、错误或已中止。

确认实际执行路径和节点结果，而不仅是 HTTP 请求成功。需要判断业务数据是否正确时，还应核对对应业务记录或外部系统证据。

## 常见问题

### 手动运行与业务事件触发有什么区别

正常业务事件由应用代码完成认证、校验、输入构造和重复事件处理；手动运行由管理员选择具体工作流版本并提交表单。两者都会执行真实节点代码。

### 为什么停用或历史版本仍可能被手动运行

手动运行是有意选择某个具体修订的管理操作，不要求该修订是当前或已启用版本。运行前必须再次确认版本和影响。

### 手动运行是否会启用所选版本

不会。运行和版本启用是两个独立操作。

### 提交成功是否表示业务已经完成

不表示。提交成功只说明运行已创建；最终结果以执行详情和业务数据为准。

### 输入错误后能否修改本次运行

不能修改已经创建的运行及其输入快照。如果运行尚未产生副作用且业务允许，可以更正输入后创建新运行；不确定时先联系开发者。
