# 检查、构建与发布

工作流从源码到运行要经过：定义检查、应用编译、Artifact 构建、运行时加载和管理员启用。每一步验证的范围不同，不能互相替代。以下命令都在应用根目录执行。

## 开发环境：保存即可试跑

`pnpm dev` 启动的服务端按需编译 `workflows/` 下的源码，不读取构建产物：

- 保存 `workflow.ts` 后，刷新管理界面就能看到一个新的未启用版本，不需要构建，也不需要重启；
- 启用这个版本后，才能设置参数和手动运行；
- 之后再修改源码会产生新的候选版本。已启用的版本保持不变，需要启用新版本才能使用修改后的代码。

开发环境按运行时实际注册的节点类型校验，所以其他插件注册的节点无需额外配置。在开发环境执行构建只有两个理由：产出可部署的 Artifact，或验证部署时会拿到什么。

## 检查工作流定义

```bash
pnpm nocobase workflow check workflows/<工作流目录>
```

检查按顺序执行五个阶段，出错时从最早的阶段开始修复：

1. `typecheck`：对定义做严格的 TypeScript 类型检查；
2. `evaluate`：在一次性的受限进程中执行 `workflow.ts`，读取默认导出；
3. `schema`：检查输入、参数和节点配置；
4. `semantic`：检查节点类型、key、分支和参数引用；
5. `compile`：检查流程拓扑完整、可达且无环。

它不会加载处理函数，也不会写数据库。加 `--ir` 可以打印编译后的扁平定义，即 Artifact 中 `workflow.json` 的内容。这个命令只认识内置节点，使用自定义节点的工作流见[自定义节点](../reference/service-api.md#自定义节点)。

## 检查处理函数和应用集成

处理函数由应用的普通服务端构建处理，所以还需要运行应用的验证：

```bash
pnpm typecheck
pnpm test
pnpm lint
pnpm build
```

重点确认：模块路径存在并命名导出 `run`；依赖声明在正确的清单中；Service token 能够解析；覆盖了代表性的分支、结果结构和副作用的幂等。

## 构建 Workflow Artifact

Artifact 是交给运行时加载的不可变工作流版本。默认应用的 `pnpm build` 已包含这一步，也可以单独运行：

```bash
pnpm nocobase workflow build
```

生产构建会收集应用服务端编译输出中相同相对路径的 `.js` 文件，并对产物内容计算摘要，存储和加载时都会重新校验。不要把输出目录指向源码或其他目录。构建 Artifact 不会启用工作流，也不能替代应用编译。

## 发布和启用新版本

1. 修改工作流和业务代码；
2. 完成定义检查、应用测试和构建；
3. 部署新的应用代码和 Artifact；
4. 管理员在管理界面中确认新版本并启用。

启用某个版本会让它成为当前版本；之前的运行仍固定在各自的原始版本上。不要编辑已存储的定义或历史运行来“更新”旧版本。

可以让 Agent 一次完成验证：

```text
请用 Workflow Skill 验证本次工作流修改：依次运行 workflow check、typecheck、相关测试、lint 和 build，逐项报告命令与结果，说明 Artifact 是否生成，以及哪些运行时和外部系统行为尚未验证。不要把没有运行的检查说成通过。
```

## 根据运行证据诊断异常

诊断时必须按运行实际使用的版本分析，不能只看当前源码。推荐顺序：

1. 记录触发结果。`skipped` 不会创建运行，不需要查找运行记录；
2. 确认工作流 key、版本和启用状态；
3. 查看运行 ID、eventKey、输入快照、状态和原因；
4. 按执行顺序找到第一个失败的叶子节点，有多次尝试时看最新一次；
5. 只读取相关节点的结果、错误和日志，留意是否被脱敏或截断；
6. 决定是修正源码、调整参数、重试原事件、创建新事件还是补偿。

在界面中查看这些信息的方法见[执行记录与诊断](../management/run-inspection.md)，交给 Agent 诊断的提示词见[提示词手册](./using-skill.md#诊断运行异常)。

## 常见故障

### 定义检查通过，但应用构建失败

定义检查不加载处理函数。检查模块是否存在、是否被应用 tsconfig 包含、依赖能否解析，以及是否命名导出 `run`。

### 触发结果为 not-found 或 disabled

`not-found` 表示没有当前定义或部署未加载它；`disabled` 表示当前版本已停用。两者都不会创建运行。

### 运行长时间处于排队中

检查工作流运行时、Worker 和队列是否已启动，以及队列中的失败、重试或死信记录。短暂排队是异步执行的正常状态。

### 处理函数加载失败

检查 Artifact 中是否包含该模块、相对路径是否一致、开发环境的 `.ts` 与生产环境的 `.js` 是否对应，以及命名导出是否存在。

### 节点结果无法保存

把 BigInt、Date、模型实例或循环对象转换为普通 JSON 值，去掉函数、Symbol 和非有限数字。

### 工作流因超时中止

查看运行的原因、工作流 `options.timeout` 的设置和日志，确认处理函数是否响应了取消信号。已经发生的外部副作用不会自动回滚，需要幂等或补偿。
