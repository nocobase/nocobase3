# 提示词手册

本页按常见任务给出可以直接复制的提示词。`<...>` 是需要替换的占位内容。每条提示词后列出了 Agent 的理想答复应包含什么，用来判断它是否真正完成了任务。

所有提示词都遵循同一原则：**描述业务，而不是指定技术方案**。你负责提供业务规则、授权和确认，Skill 负责让 Agent 检查真实代码、使用当前版本的写法、报告验证结果。审核要点汇总在[与 Agent 协作开发](./index.md#审核清单)。

## 判断是否适合工作流

```text
<业务过程描述，例如：客户提交入驻资料后，检查资料完整性、计算风险，并根据结果开通账号或标记为待处理。运营人员需要看到每次处理进行到哪一步。>
请先检查当前应用的能力，判断应该使用工作流、普通业务代码还是两者结合，说明理由，暂时不要修改代码。
```

理想答复：选型理由；哪些动作留在 Service 中；是否存在现有节点无法表达的等待或审批；需要你确认的数据结构。

## 创建工作流

一个可执行的需求至少包含触发事件、业务规则、管理员配置、副作用和重复事件处理：

```text
<触发事件>后，在后台<处理内容>。<业务规则，例如：风险超过管理员配置的阈值时记录为需要人工处理，否则记录为自动通过。>
管理员需要查看每次处理的路径和结果；<重复事件规则，例如：同一版报价重复提交时不能重复记录决定。>
请先检查相关的数据结构、Service 和已有节点，再实现并验证。
```

理想答复：流程结构图；输入与管理员参数；每个节点的职责和副作用；运行过的检查命令及结果。工作流目录名和节点 key 由 Agent 决定，不需要你提前命名。

## 修改已有工作流

```text
将现有<工作流的业务名称>修改为：<新的规则>。
请先找到负责它的工作流和 Service，说明本次修改对输入、参数、节点结果和已发布版本的影响，再修改、测试。
```

理想答复：定位到的工作流目录；影响分析；修改后的验证结果。Agent 应通过工作流目录、标题、说明和节点来确认目标，而不是猜测数据库 ID。历史运行不会被修改，部署后管理员需要启用新版本。

## 接入业务事件

编写工作流不会自动监听任何业务事件，需要单独接入：

```text
把<业务事件，例如：报价提交成功>接入<工作流的业务名称>。
同一业务事件重试时使用相同的事件标识，分别处理 accepted 和 skipped 两种结果，并补充测试。不要新增通用的公开触发接口。
```

理想答复：在哪段业务代码中触发；事件标识如何构造；`skipped` 时的处理方式；业务写入本身如何保证幂等。

## 定时触发

```text
请让<工作流的业务名称>每天 <时间>（<时区>）自动执行一次，输入为 <输入内容>。
使用定时任务的内置 workflow 执行目标，同步后告诉我如何在界面中确认执行记录。
```

理想答复：定时任务 key、Cron、时区、目标工作流目录和输入；同步结果；在哪里查看定时任务和工作流的执行记录。定时任务本身的管理见[定时任务](../../scheduler.md)。

## 诊断运行异常

提供运行 ID，或足以唯一定位这次运行的工作流、时间和业务事件：

```text
请诊断工作流运行 <运行 ID>。确认它实际使用的版本和执行路径，找到第一个失败的叶子节点，查看该节点最新一次尝试的错误和日志，区分根因与向父节点传播的错误。
只读取证据，不要重新运行、修改参数或改写数据。
```

理想答复：版本、运行状态、失败节点及原因、内容是否被脱敏或截断，以及建议的恢复方式。诊断和恢复是两步：需要重跑、启用版本或修改参数时，在诊断完成后单独授权。

## 管理操作

Agent 也可以代你启停工作流、修改参数或手动运行，但这些操作会改变应用状态，必须明确授权：

```text
请在<开发 / 测试>环境中启用<工作流的业务名称>的最新版本，并用输入 <输入内容> 手动运行一次。完成后报告运行 ID、最终状态和各节点结果。
```

手动运行会执行真实业务代码。在生产环境操作前，确认目标版本、输入和可能产生的副作用。

## 迁移旧写法

早期版本的工作流使用 `defineWorkflow()`、`RunInstruction.create()` 和 JSON Logic 条件表达式。JSON Logic 已移除，新代码推荐使用类型化 builder：

```text
请把 workflows/<目录名> 迁移到当前推荐的工作流写法。保持目录名、节点 key、顺序和分支不变，把条件表达式改写为返回布尔值的处理函数，并运行 workflow check 和相关测试。
```

理想答复：迁移前后行为是否一致（尤其是条件判断和缺失值的处理）；验证结果。迁移会产生一个新版本，历史运行不受影响。

## 常见问题

### 需要在提示词里点名 Skill 吗

通常不需要。需要限定 Agent 的做法时，可以加一句“请使用 Workflow Skill 分析，先不要修改代码”。

### Agent 选择的工作流不对

如果你没有给出目录名，Agent 会枚举应用的工作流目录，按标题和说明匹配。存在多个相似候选时，它应该列出来让你选择；直接告诉它目录名最可靠。
