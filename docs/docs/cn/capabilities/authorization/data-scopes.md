# 数据范围与规则

数据范围决定已获准执行某个操作的人能处理哪些记录。范围选项由业务系统提供，例如全部、本人负责、本人创建、本人编制、本区域和自定义条件。请选择符合真实职责的范围；“本人”取决于系统定义的归属字段，不一定等同于创建人。

## 三种规则如何配合

权限集选择的范围、默认数据范围和共享范围可以增加可访问的记录；限制规则再收窄结果。这不是“有权限集范围就忽略默认范围”的覆盖关系。例如把编辑默认范围设为“所有报价”，会扩大原本“仅本人编制”的编辑范围。

| 需求                                 | 使用                           |
| ------------------------------------ | ------------------------------ |
| 所有报价查看者都能查阅非保密参考资料 | [默认数据范围](default-access) |
| 某份报价交给指定提案团队处理         | [共享规则](sharing-rules)      |
| 该团队任何协作都不能涉及保密报价     | [限制规则](restriction-rules)  |

三种规则都不能赋予缺失的业务操作、字段或页面权限。给某人共享一份报价，不会自动让他获得“提交报价”能力。

## 多表操作与关系

提交报价可能同时要求报价可修改、父项目可读取。共享报价不等于共享项目；两个范围都满足后，业务状态也必须允许提交。例如已提交报价不能再次作为草稿提交，这是业务校验。

给订单关联交付团队、维护交付检查项、修改协作关系备注，属于不同的关系能力。能看团队名称不代表能改团队资料。可关联哪些团队、可编辑哪些关联字段，需要开发者明确声明，不能靠普通共享规则推断。

## 范围不是逐行拼接字段

系统会把授权转换成数据库策略。不同权限来源若在不同记录上提供不同字段或关系能力，合并时可能采用更严格的交集。遇到“单独可用、组合后变窄”的情况，应让开发者检查操作拆分与策略，而不是添加全部数据权限绕过。
