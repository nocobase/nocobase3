# 多语言

NocoBase 3 的应用默认就支持多语言，内置中文和英文。

如果内置的两种语言够用，这一页你只需要看前两节。需要增加一种语言，或者想让应用默认显示中文，再往下看——这些都可以让 Coding Agent 完成。

## 切换语言

点开右上角的头像，选择「语言」，即可切换语言。

![switch language](https://static-docs.nocobase.com/20260911144348.png)

切换立即生效，页面不会刷新，插件提供的界面也会跟着变。

**语言切换是用户级别的。** 它保存在当前浏览器里，刷新后还在，但不会跟着账号同步到其他设备。你切换成中文，不会影响别人看到的语言，也不会改变应用的默认语言。

## 加一种新语言

应用支持哪些语言，由应用自己的翻译文件决定——**加一个语言文件，就是加一种语言**。

翻译文件分前后端两处：`client/locales/` 决定切换菜单里出现哪些语言，`server/locales/` 决定服务端能用哪种语言回应。两边支持的语言要保持一致，否则会出现界面切过去了、服务端却没有这种语言的情况。

可以把需求交给 Coding Agent，说语言的名字就行：

```text
给我的应用增加西班牙语，前后端都要加上。

完成后运行 pnpm nocobase app i18n check 和 pnpm typecheck 确认。
```

它会创建语言文件、登记到加载列表，并检查两边是否一致。完成后刷新页面，切换菜单里就会多出这一项——菜单里显示的名字由语言代号自动得出，不需要你另外配置。

<!-- 需要一张切换菜单中新增了一门语言（比如 español）的截图。 -->

如果只加了一边，可以用这个命令查出来：

```bash
pnpm nocobase app i18n check
```

它会指出哪种语言只在一侧声明了。两边一致时命令什么都不报。

## 设置默认语言

默认语言指的是**没有选过语言的人**第一次打开应用时看到的语言。在 `config.yml` 里配置：

```yaml
i18n:
  defaultLocale: zh-CN
```

不配置时默认为 `en-US`。改完刷新页面生效。

:::tip 已经选过语言的人不受影响

默认语言只对没做过选择的浏览器起作用。如果你改了这个配置却发现自己看到的语言没变，多半是因为你之前手动切换过——换一个浏览器，或者清掉站点数据就能看到效果。

:::

默认语言还有第二个作用：某段文字在当前语言里没有翻译时，会回落到默认语言。

## 插件的语言

装一个插件，它会带来自己的翻译，但**不会往你的切换菜单里加语言**。菜单里有哪些语言，始终由你的应用决定。

反过来，你的应用支持的语言，插件不一定都翻译了。这时候没翻译的部分会按这个顺序回落：

```text
当前语言  →  应用的默认语言  →  英文
```

举个例子：应用默认中文，你加了西班牙语，而某个插件只翻译了中文和英文。一个西班牙语用户看到的界面里，你自己写的部分是西班牙语，这个插件的部分是英文——不是中文。最后一步回落到英文，是因为对一个看西班牙语的人来说，英文比中文更可能读得懂。

如果你希望插件的某段文案也用你的措辞，不需要等插件更新，也不要去改插件源码。在应用自己的翻译文件里覆盖它就行，做法见[应用开发 / 多语言](../app/i18n.md)。

## 哪些地方会受语言影响

| 位置           | 跟随什么语言                               |
| -------------- | ------------------------------------------ |
| 界面上的文字   | 当前浏览器选择的语言                       |
| 接口返回的报错 | 发起这次请求的会话的语言                   |
| 邮件、通知     | **收件人**的语言，不是触发这件事的人的语言 |
| 主题名称       | 当前语言，翻译写在应用的语言文件里         |

最后一条容易被忽略：主题的名称也是要翻译的文案，新增主题时记得一并加上。详见[主题](./theme.md)。

## 常见问题

### 切换了语言，但有一部分还是英文

这部分文案属于某个插件，而它没有翻译这种语言。回落到英文是预期行为，不是故障。需要中文的话，在应用自己的翻译文件里覆盖对应的 key。

### 加了语言文件，切换菜单里却没有

先确认加的是 `client/locales/`——切换菜单读的是这一侧。然后运行 `pnpm nocobase app i18n check` 看看两边是否一致。另外，新增语言文件后需要重启开发服务。

### 界面切过去了，但服务端返回的内容还是旧语言

通常是只在 `client/locales/` 加了语言，`server/locales/` 没加。服务端不认这种语言，就会继续用原来的语言回应。

### 同一个账号开了两个标签页，语言互相影响

服务端记录的语言存在会话里，同一个账号的多个标签页共用一个会话，所以后切换的会覆盖先切换的。界面本身不受影响，各个标签页显示各自的语言；受影响的是服务端产生的内容，比如报错信息。这是当前的已知限制。
