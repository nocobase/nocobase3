# 模板打印

模板打印适合按固定版式生成合同、订单、发票和报表。你提供模板、数据范围和输出要求，应用 Agent 根据模板打印 Skill，在当前应用中实现数据填充、文件下载和需要的打印入口。

`@nocobase/app-plugin-template-print` 只提供 Skill 和配套参考资料。安装后，Agent 可以读取实现指导；打印按钮、模板管理页面和渲染服务需要根据你的业务需求开发。插件本身不会创建这些功能，也不需要注册 Client 或 Server 入口。

## 安装和同步 Skill

在目标应用根目录安装插件，并同步它提供的 Skill。以下命令用于安装已发布的版本：

```bash
pnpm add -D @nocobase/app-plugin-template-print
pnpm nocobase skills:sync --package @nocobase/app-plugin-template-print --json
```

如果正在 NocoBase 3 源码工作区中开发，且工作区已经包含这个插件，可以在目标应用目录使用工作区依赖：

```bash
pnpm add -D '@nocobase/app-plugin-template-print@workspace:*'
pnpm nocobase skills:sync --package @nocobase/app-plugin-template-print --json
```

尚未发布到所用 registry 的版本需要使用工作区包或本地打包产物。`workspace:*` 仅适用于同一工作区，不能在独立应用中用来下载 npm 包。

同步成功后，应用中会出现 `.agents/skills/nocobase-app-plugin-template-print/SKILL.md` 及其参考资料。升级插件后再次运行同步命令。该目录是生成的本地内容，下次同步会整体替换；业务代码和模板应保存在应用自己的目录中。

## 准备打印需求

第一次实现时，准备一份实际模板和一条有代表性的业务记录，并说明：

| 内容       | 示例                                         |
| ---------- | -------------------------------------------- |
| 使用位置   | 在订单详情页添加“打印合同”按钮               |
| 模板和版式 | 使用现有 DOCX 合同，保留页眉、表格和签名区域 |
| 填充数据   | 客户名称、订单编号、明细、数量、单价和合计   |
| 打印范围   | 当前订单、选中记录、当前页或全部筛选结果     |
| 输出方式   | 下载 DOCX、下载 PDF，或打开 PDF 后打印       |
| 使用权限   | 只能打印当前用户有权查看的订单及附件         |

已有模板可以直接提供给 Agent；尚未确定字段标记时，让 Agent 根据实际数据结构补充。没有模板时，描述所需版式，并先检查 Agent 制作的模板样例。

这里的 Agent 是在应用源码目录中工作的开发 Agent。业务用户在功能开发完成后使用页面上的按钮，不需要学习 Skill 或编写提示词。

## 让 Agent 实现打印功能

在目标应用目录中使用能够读取项目 Skills 的开发工具，描述模板打印需求。需要明确指定时，可以在需求中写出 `nocobase-app-plugin-template-print`。

### 打印一份订单合同

> 请使用 nocobase-app-plugin-template-print Skill，为订单详情页添加“打印合同”按钮。使用我提供的 DOCX 模板，填入当前订单的客户名称、订单编号、明细和金额，保留模板版式，支持下载 DOCX。只能使用当前用户有权查看的数据。请先检查现有订单字段和页面，再实现并用实际模板验证。

Agent 应复用当前应用的数据访问、权限和页面结构，按需要添加渲染依赖。完成后，打开一条订单，下载生成的合同，检查字段、明细行数、金额和分页是否符合模板要求。

### 批量打印

批量打印时要明确记录范围和文件组织方式。例如：

> 在订单列表添加“导出发货清单”。使用提供的 XLSX 模板，只包含我勾选的订单，按订单编号排序，每条订单显示收货人、地址和商品明细，输出一个 XLSX 文件。没有勾选时提示选择记录；超过 200 条时提示缩小范围。请验证筛选后跨页勾选的行为，以及无权限记录的处理方式。

“选中记录”“当前页”和“全部筛选结果”对应不同的查询范围。不要只写“打印列表”，否则 Agent 无法确定分页、勾选和筛选之间的关系。记录上限由业务和部署资源决定，插件没有预设运行时上限。

### 添加图片、二维码或 PDF

可以在已有功能上继续提出具体要求：

> 合同中需要显示公司 Logo 和当前订单的附件图片，并加入一个指向订单页面的二维码。增加 PDF 下载，使用部署环境的字体验证中文、图片大小和分页。无权读取的附件不得出现在文档中；转换失败时在页面显示可理解的错误。

DOCX、XLSX 和 PPTX 可以作为实现时选择的模板格式，实际支持范围以 Agent 完成并验证的功能为准。图片所在位置也需要说明，例如正文、页眉、页脚或 Excel 单元格。二维码与一维条码是不同需求，需要一维条码时应明确编码类型。

PDF 转换通常需要额外的服务端转换环境。例如，使用内嵌 Carbone 引擎的转换路径时，需要部署兼容的 LibreOffice 和字体。让 Agent 明确所选方案的部署要求，并验证最终 PDF。下载或打开 PDF 后，用户可以通过查看器的打印功能选择打印机；静默调用本地打印机需要单独的实现方案。

### 管理多份模板

只有需要业务用户维护模板时，才要求 Agent 实现模板管理。例如：

> 销售合同有国内版和海外版。请允许管理员上传和替换模板，销售人员打印时选择适用版本。模板需要绑定订单数据，替换模板后仍能正确处理正在生成的合同。普通销售人员不能修改模板。

固定模板可以随应用维护。上传、版本管理、选择模板和管理权限是额外的业务功能，需要在需求中说明。

## 检查交付结果

让 Agent 提供模板样例、生成文件、实际执行的检查，以及尚未验证的格式或部署条件。重点核对：

- 文件能在目标 Office 查看器中打开，没有修复提示，字段和重复明细正确。
- 打印范围与勾选、筛选、分页要求一致，不包含无权查看的数据或附件。
- 空明细、长文本、多页表格、中文字体和图片在实际版式中显示正常。
- 下载文件名和格式正确；模板缺失、无数据或转换失败时有明确提示。
- 需要 PDF 时，在部署环境验证转换、字体和分页，而不仅是在开发机器上下载成功。

同步 Skill 只说明 Agent 能读取指导资料。功能完成还需要业务页面、服务端实现和生成文件的验证。

## 常见问题

### 安装后为什么没有打印按钮

这个插件提供开发指导，按钮位置和打印行为由应用需求决定。完成安装和同步后，继续向应用 Agent 提出具体的打印需求。

### Agent 没有找到 Skill 怎么办

确认开发工具打开的是目标应用目录，插件已作为该应用的直接依赖安装，并且同步命令成功。再让 Agent 读取 `.agents/skills/nocobase-app-plugin-template-print/SKILL.md`。如果文件存在但工具未发现，检查该工具的项目 Skill 加载方式。

### 生成文件版式不对怎么办

同时提供原模板、生成文件、使用的查看器，以及具体差异，例如“第二页表格被截断”或“中文字体被替换”。让 Agent 区分数据填充、Office 版式和 PDF 转换的问题，再验证修改后的文件。
