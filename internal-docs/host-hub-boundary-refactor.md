# Hub / Host 职责拆分进度

## 本轮已实现

- Hub 保留数据库目标和私有目标配置文件，Host 不依赖 Hub 数据库。
- 部署配置经管理协议传递内容和 revision；Host 决定运行配置路径并原子写入。
- Host 在切换成功后清理旧运行配置，失败后清理独立候选配置。
- Save and publish 由 Host 队列执行运行文件写入和 reload。
- Restart 在 Host 内部完成，与部署和配置发布共用执行队列。
- Remove 的 Host 运行目录清理下移，保持现有删除应用及持久化数据语义；Hub 只清理自己的目标配置、Release 和记录。
- Supervisor 不再维护应用部署快照；Host 就绪通知 Hub 从持久化目标重新生成恢复请求。
- IPC 生命周期请求先确认接受，接受后不再受请求等待期限限制，完成后返回结果。
- Hub 页面按业务模块拆分，未修改基础 UI 组件。

## 尚未完成，不能按生产闭环验收

- IPC 完成结果仍绑定原请求 ID，没有独立操作 ID、结果查询、确认和断线补同步。
- Hub 对通信失败仍可能直接记为部署失败。接受确认丢失、进程退出或数据库更新失败后的结果协调仍需实现。
- Hub 启动仍会终结未完成历史操作，而不是先和 Host 核对结果。
- 恢复失败现在有日志和下一次 Host 就绪触发，但没有独立的协调重试机制。
- Host 的全局执行队列尚未细化为每应用互斥；不同 App 是否允许并行仍需结合共享 QueueManager 限制处理。
- 独立 Host 仍走目录目标源；配置发布等管理接口尚未统一到同一执行服务。
- 目标配置目前按文件持久化，未引入配置版本库或数据库 secret 明文存储。

完整异步协议应以操作 ID 关联目标与结果，不能只删除超时。应补充断线、重复提交、迟到结果和切换中途退出的故障测试。
