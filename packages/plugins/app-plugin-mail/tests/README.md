# Mail regression tests

Run `pnpm --filter @nocobase/app-plugin-mail test` from the repository root. This runs all plugin tests and V8 coverage, including files that no test imports. The same command runs through the root test script in CI. Coverage reports are written to the package's ignored `coverage/` directory. Minimum coverage is enforced by `vitest.config.ts`; do not lower a threshold to accommodate an untested feature.

For a focused diagnostic run without enforcing the whole-package coverage floor, use `pnpm --filter @nocobase/app-plugin-mail exec vitest run tests/api-integration.test.ts` and replace the filename as needed.

## Regression boundaries

| Tests                                       | What they verify                                                                                                                                                                                         | External boundary                                                                                       |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| `api-integration.test.ts`                   | Real MailClient, HTTP routing, service, adapter resolution, credentials, SQLite, queue and outbox: connect, initial sync, read, reply, idempotent retry, delivery logs, template CRUD and user isolation | Authentication/authorization fixtures and a deterministic provider; requests go through Hono in process |
| `preferences-persistence.test.ts`           | Persisted templates, label uniqueness, signature defaults, identity edits and cross-user/cross-account rejection                                                                                         | Real in-memory SQLite with the production migration                                                     |
| `attachment-storage.test.ts`                | Actual attachment bytes, ownership and expiration checks, filename/size validation, database failure compensation and cleanup                                                                            | Temporary local files behind the disk interface; real SQLite metadata                                   |
| `adapter-resolver.test.ts`                  | Missing providers, configuration validation, default configuration and adapter construction failures                                                                                                     | Provider factory fixtures                                                                               |
| `mail-log-pages.test.tsx`                   | Send/sync states, safe log fields, empty/error/recovery states, combined filters, action eligibility, retry and cancel                                                                                   | Real React and i18n in jsdom; MailClient responses are fixtures                                         |
| `mail-template-manager.test.tsx`            | Create/edit/delete, duplicate-submit prevention, failure retention, retry and editor reset                                                                                                               | Real React in jsdom; MailClient responses are fixtures                                                  |
| `adapters/imap-smtp/imap-smtp.test.ts`      | Verification cleanup, credential persistence boundaries, cancellation, UIDVALIDITY reset, folder/flag mapping, SMTP response classification and submission certainty                                     | IMAP and SMTP library doubles                                                                           |
| `adapters/imap-smtp/smtp-transport.test.ts` | Nodemailer's actual SMTP exchange and MIME generation, Bcc envelope privacy, reply headers, attachment bytes and 450/550 responses                                                                       | Minimal loopback SMTP fixture; no external account or credentials                                       |

The SMTP transport test binds an ephemeral port on `127.0.0.1`. A sandbox that prohibits listening on local sockets must allow this test to run outside that restriction. It does not send mail to an external service. Every test closes its connections and removes temporary files.

SMTP regression expectations follow [RFC 5321 section 4.2.1](https://www.rfc-editor.org/rfc/rfc5321.html#section-4.2.1): 4xx replies are temporary and 5xx replies are permanent. A transport timeout after submission starts leaves delivery uncertain; attachment preparation failures occur before submission and remain definite failures.

## Remaining environment-dependent verification

These tests do not establish real Gmail or Microsoft OAuth/provider interoperability, complete IMAP server compatibility, browser layout/accessibility, or multi-process recovery against PostgreSQL/MySQL. Those require dedicated environments. The client-to-database suite is an integration test, not a browser E2E test; the local SMTP fixture exercises a real socket and library but is not a full mail server. The manual product checklist under `docs/zh-CN/test-checklist.md` retains its own execution status and must not be marked complete merely because these tests pass.
