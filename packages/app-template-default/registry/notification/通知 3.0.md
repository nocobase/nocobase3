# 通知 3\.0

## 基本概念

- Channel：定义通知通过哪种方式触达用户，例如站内信、邮件、短信或 Push。

- Provider：定义某个通知渠道具体使用哪个第三方服务发送，例如SMS 有阿里云短信、Twilio、AWS SES。

- Transport：对某个 Provider 的具体发送适配实现，可能有多种实现（后续在 nocobase 中不使用该概念，默认一个 provider 对应一个实现）

### 消息发送

- **多渠道发送**：一次事件可同时通过站内信、Email、SMS、Push 等 Channel 发送。

- **Provider 路由**：根据地域、账号、租户、用户属性等信息动态选择 Provider。

- **Provider Fallback**：同一 Channel 下可配置多个 Provider，按优先级尝试；当前 Provider 发送失败后自动切换下一个。

- **Provider 回执**：接收 Provider 的发送状态回调，并更新 Delivery 状态。

- **接收者与地址解析**：支持基于用户 ID、用户筛选条件等解析接收者，并自动获取对应 Channel 所需的 email、phone、push token 等地址。

- **站内通知 Inbox**：支持通知列表、未读数、已读/未读、全部已读、删除及实时更新。

- **多语言 / 国际化**：根据 Recipient 的 locale 渲染对应语言的通知内容。

- **延迟 / 定时发送**：支持延迟指定时间发送，或在指定时间点发送。

- **发送日志 / 审计**：记录 messageId、Recipient、Channel、Provider、状态、重试次数、失败原因、触发来源等信息。

- **幂等 / 去重**：如果请求中提供 `idempotencyKey`，同一 key 只允许成功触发一次通知。





### 异步任务

- **队列异步发送**：支持通过队列执行通知发送任务。

- **任务优先级**：支持验证码、告警等高优先级任务优先于营销、普通提醒。

- **并发控制**：支持全局、Channel 或 Provider 级别的发送并发限制。

- **失败重试**：支持配置重试次数、重试间隔，并可扩展指数退避策略。

- **任务超时**：支持发送任务超时控制。

- **失败状态记录**：任务达到最大重试次数后进入最终失败状态，并记录失败原因。



### 消息模板

- **消息模板**：按事件 / 通知类型维护模板，不同 Channel 可配置独立模板，支持变量、条件和多语言。

- **接收者模型**：统一 Recipient / Subscriber，保存 email、phone、locale、country、timezone、push token 等。Novu 的 Subscriber 就承担这一角色。

- **群组 / Topic**：一个事件发给项目成员、组织成员、某个 Topic，而不是每次展开 userId 列表



### 流程

```Plain Text
  ↓
Delivery
  ↓
Receipt / Audit
```
