Correct the AI employee Skill on chat surfaces, MCP credentials, keys and unattended runs

- **Chat surfaces.** `ChatDialog`, `ChatSidePanel` and `ChatSurface` are controlled, so a surface opened by `AIChatFloatingTrigger` takes `open` from `useAIChatControllerState(controller)` and wires `onOpenChange` to `controller.setOpen`; the Skill shows the complete trigger-and-surface wiring, points at the plugin's floating demo, and adds a completion check that clicking the trigger opens the chat. An employee whose own models are all disabled cannot be chatted with, and the server refuses to run it.
- **MCP.** Credentials go in `headers` or `env`, never in `url` or `args`, which the settings API returns unmasked; expanded values are stored in plain text on the server's row; removing or renaming a server discards its switch and tool permissions; an unreachable server is retried only when the client is rebuilt; and a permission can be set only for a tool a connected server lists.
- **Errors.** Over HTTP a chat always answers `200` with an SSE body, and a failed run's `error` event carries the agent's `code`. `createAgent()` resolves its model at creation, while `createAIEmployee()` fails there only when no model is usable and otherwise when the run starts.
- **LLM key.** In `.env`, only a `$` that would start a variable reference is escaped, and a key containing a backslash followed by `n` or `r` cannot be stored there; in `config.yml`, a key containing `${NAME}` cannot be stored because the plugin expands it. The marker for the `config.yml` option is single-quoted, a command must write through a symbolic link, keep an existing file's permissions, read leading and trailing spaces, and be verified with a wider set of fake values. `.env.local` and the environment `pnpm dev` starts from both override `.env`.
- **Unattended runs.** The conversation is created with the same `skillSettings` as the agent, so a later resume over HTTP keeps the allowlist; `skills` with `skillsVersion` narrows the Skills; the interrupt loop is bounded; a date-based job passes `state.timezone`; and the actor carries its real roles with `isRoot: false`. A fixed agent's `getSkill` loads only the Skills it was given, so a chain is listed in full, and a mistyped Skill name is dropped silently.
- **Registrar.** `AIResourceRegistrar` registers tools, Skills and employees; MCP servers come only from `config.yml`.
